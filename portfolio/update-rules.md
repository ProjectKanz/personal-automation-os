# Portfolio Update Rules

These rules keep public documentation aligned with the current V3.4 personal MVP positioning.

## Update changelog when:
- A bug is fixed
- A helper is added
- A module is refactored
- A small technical improvement is completed

## Update README when:
- A feature or module changes the project story
- A milestone version is completed
- The demo flow changes

## Update CV bullet bank when:
- A new skill is demonstrated
- A new role-targeted positioning becomes available
- A measurable result or stronger evidence is added

## Update LinkedIn draft when:
- A milestone is understandable to non-technical audiences
- There is a clear before-after story
- There are screenshots or demo evidence ready
- The public positioning changes, such as V3.4 Web Command Center

## Do not update public CV/LinkedIn for:
- Small helper functions
- Minor wording changes
- Internal refactors without a clear story

## Public demo safety

- Use mock or sanitized data in screenshots and clips.
- Do not show real CVs, private spreadsheet URLs, Telegram setup screens, API keys, Drive links, private job applications, or real trading records.
- Keep claims honest: personal MVP, prototype, portfolio case study, and AI-assisted workflow.

## V2.8 - Portfolio Visual Dashboard Layer

Added a separate visual dashboard sheet for portfolio presentation.
The dashboard reads from operational sheets but does not modify Daily_DB, Log, Applications, or AI_Audit.
This separates the operational data layer from the visual presentation layer.

## V3.4 - Web Command Center

Use the web command center as the main demo surface for public portfolio assets.
Show the workflow with mock data, then explain the private operational sheets as the underlying data store.
